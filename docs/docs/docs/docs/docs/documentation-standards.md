# Purpose

This document establishes the documentation standards used throughout the House of Lady Amour project.

Consistent documentation improves collaboration, maintainability, onboarding, and long-term project success.

---

# Documentation Principles

Every document should be:

- Clear
- Professional
- Well organized
- Version controlled
- Easy to maintain
- Easy to read
- Written for both technical and non-technical audiences

---

# Required Header

Every major document should begin with the following information.

---

Document Title

Document Owner

Version

Status

Last Updated

Related Documents

---

Example

# Site Map

Owner: Marsharine A. Simpson

Version: 1.0

Status: Draft

Last Updated: August 2026

Related Documents

- Product Requirements Document
- Software Architecture
- User Personas

# Writing Guidelines

Use:

Short paragraphs

Descriptive headings

Bullet lists

Tables where appropriate

Simple language

Consistent terminology

---

Avoid:

Walls of text

Unexplained acronyms

Large paragraphs

Inconsistent formatting

---

# Markdown Standards

Use ATX headings.

Example

# Heading

## Heading

### Heading

---

Use fenced code blocks.

Use tables when appropriate.

Use ordered lists for procedures.

Use unordered lists for reference material.

---

# File Naming Convention

Use lowercase.

Separate words with hyphens.

Examples

project-charter.md

software-architecture.md

testing-strategy.md

user-personas.md
